This guide shows how to load, play and control Spine animations in PixiJS with pixi-marrow, one step at a time. You need no experience with Spine. The examples of the guide use the symbols of the slot game Bzzz, which this site includes. So many examples look like slot symbols, but nothing in the guide is specific to slots.

## Install

```bash
npm install pixi-marrow@next pixi.js
```

`pixi.js` is the peer dependency that pixi-marrow needs, from version {facts.floor.pixiShort}. `pixi-silk` is an optional peer. Only the [debug overlays](/debug/) need it. The package is a pre-release, on the `next` tag of npm.

The package is ESM only, so a game needs a bundler such as Vite, or a browser that loads modules. [Good to know](/good-to-know/#esm-and-bundlers) says more.

## One complete file

<Snippet source={source} regions="complete" />

This file is a whole game. It makes a Pixi application, loads a skeleton, puts it in the middle of the screen and plays a loop.

- `MarrowSpine.load` reads the skeleton, its atlas and the page images. `skeleton` is a `.skel` or `.json` export of Spine 4.1, 4.2 or 4.3. The page images load from the same place as the atlas.
- `hero` is a Pixi `Container`. Move it, scale it and add it to the stage like any other.
- `play` starts an animation now. `loop: true` repeats it until something else plays.

For a name that the skeleton lacks, `play` throws a `MarrowError` that lists the valid names. [Warnings and errors](/warnings/) lists every error code.

The renderer must be WebGL2 or WebGPU. Pixi picks WebGL2 by default, and `preference: 'webgpu'` in `app.init` asks for WebGPU.

## What Spine is

There are two ways to animate a 2D character. Watch the same wave made both ways:

<Diagram name="skeletal" height={300} rows={2} caption="Left, a wave from a sprite sheet of 8 pictures, shown one after the other. Right, the same wave from a skeleton: 2 pictures and a bone that turns the arm." />

**Frame by frame**, an artist draws every picture of the motion, and the game shows them one after the other. The left side has 8 pictures, and the arm jumps from one to the next. More smoothness means more pictures, and more pictures mean more memory and longer loading.

**Skeletal animation**, which Spine does, splits the character into parts: a body, an arm. A bone holds each part. The animation stores only a few numbers per bone, such as "the arm turns from -35 to 55 degrees". In every frame the runtime computes where each bone is and draws the parts there. So the motion is smooth at any frame rate, and the files stay small. Two animations can also blend into each other, which pictures cannot.

## What a runtime does

The Spine editor exports three kinds of files:

- A skeleton file, `.skel` or `.json`, with the bones, the parts and the animations, all as numbers.
- An atlas file, `.atlas`, that says where each part lies in the images.
- The images, such as `.png`, `.webp` or `.avif`, with all parts packed into one or a few pages.

A runtime reads these files and does the work in every frame:

1. It finds the pose of each bone at the current time.
2. It places the parts.
3. It has the GPU draw them.

pixi-marrow is a runtime for PixiJS v8. [One frame](/how/frame/) shows the whole way from the time to the pixels. If pixels, transforms, triangles and draw calls are new to you, read the [Basics](/basics/pixels/) first: five short pages with animations.
