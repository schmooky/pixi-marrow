A rule names one cause of cost in a scene. Each rule has a stable id, from `MARROW001` on. A warning, a row of `perf.report()` and a hit of `diagnose` each carry the id and a link to its heading on this page.

The same list is in the package as `perf-rules.json`, and on this site at [/perf-rules.json](/perf-rules.json).

## Find the rules that hit

Add one line to the development build of the game. It puts the hook `__PIXI_MARROW__` on `globalThis`. The package registers nothing until that call.

```ts
import { installDevtools } from 'pixi-marrow/diagnose';

installDevtools({ root: app.stage, renderer: app.renderer });
```

Then ask the hook in the console of the browser. A coding agent that can run code in the page calls the same functions.

```ts
__PIXI_MARROW__.diagnose().hits; // the causes that one look finds
const watching = __PIXI_MARROW__.watch(); // note the counters now
watching.report().hits; // some frames later: also the causes that show over time
__PIXI_MARROW__.inspect(); // each skeleton as plain data
JSON.stringify(__PIXI_MARROW__.tree()); // the tree, to diagnose somewhere else
```

A hit is a plain object. `id` is the rule and `node` is the path of the skeleton, such as `stage/reels[2]/MarrowSpine`. `cause` is the path of the display object that causes the hit. `measured` holds the numbers, `fix` says what to change, and `docs` links here.

Without a browser, save the tree as a file and run the command line tool. It runs the rules that one look finds.

```bash
pixi-marrow diagnose tree.json
pixi-marrow rules --json
```

`installDevtools({ warn: true })` also prints each hit once per rule and skeleton. Pass `ticker: app.ticker` and the hook looks again every 120 ticks.

## Costs

| Cost | What grows |
| --- | --- |
| draw calls | The commands from the CPU to the GPU in a frame. |
| CPU time for vertices | The work to place vertices and to write their colors. |
| CPU time for the pose | The work of the animations and the constraints. |
| bytes sent to the GPU | The vertex and index data that a frame uploads. |
| pixels drawn more than once | The work of the GPU for pixels that a later slot hides. |
| memory | Typed arrays, GPU buffers and textures. |

## MARROW001

**A display object above a batched skeleton moves.** Its short name is `moving-ancestor-batched`, and its level is `warn`.

| What | Details |
| --- | --- |
| Cost | CPU time for vertices, bytes sent to the GPU |
| Found by | two looks |
| Pattern | A skeleton in the batched mode, or a container above it, changes its position, scale or rotation in each frame. No render group lies between that container and the skeleton. |
| Runtime | A batch holds vertex positions in the space of its render group. The runtime places every vertex of the skeleton again and uploads it, also when the pose is at rest. |
| Source | `src/render/batch-element.ts` |
| Check | `totals.transformReplaces` grows from frame to frame. |
| Fix | Set `isRenderGroup: true` on the container that moves, or set `renderMode: 'mesh'` on the skeleton. |

## MARROW002

**The alpha or the tint above a batched skeleton changes.** Its short name is `ancestor-tint-animated`, and its level is `warn`.

| What | Details |
| --- | --- |
| Cost | CPU time for vertices, bytes sent to the GPU |
| Found by | two looks |
| Pattern | The alpha or the tint of a skeleton in the batched mode, or of a container above it, changes in each frame. No render group lies between that container and the skeleton. |

| Source | `src/render/batch-element.ts` |

## MARROW003

**An alpha or a blend mode above the skeleton stops occlusion and the idle image.** Its short name is `ancestor-alpha-or-blend`, and its level is `info`.

| What | Details |
| --- | --- |
| Cost | pixels drawn more than once |
| Found by | one look |
| Pattern | The skeleton or a container above it has an alpha other than 1, or a blend mode other than `normal` and `inherit`. The skeleton has outlines or the setting `idleCache`. |
| Runtime | An opaque slot then shows what is behind it. The runtime draws every covered slot again while that holds, and the idle cache drops its image. |
| Source | `src/render/gate.ts` |
| Check | `cuts.blockedBy` holds `alpha-or-blend`, and `cuts.coveredSlots` is 0. |

## MARROW004

**Another display object draws between two batched skeletons.** Its short name is `batch-broken-by-sibling`, and its level is `warn`.

| --- | --- |
| Cost | draw calls |
| Found by | one look |

## MARROW006

**A blend mode splits the draws of a skeleton.** Its short name is `blend-run-split`, and its level is `info`.

| What | Details |
| --- | --- |
| Cost | draw calls |
| Found by | one look |
| Pattern | A visible slot blends with multiply or screen. Or the skeleton, or a container above it, has a blend mode other than `normal` and `inherit`. |
| Runtime | Normal and additive slots share one draw. A slot that multiplies or screens starts a new draw, and so does a skeleton with another blend mode than the one before it. |

## MARROW021

**A page texture blocks the cuts of overdraw.** Its short name is `page-texture-blocks-cuts`, and its level is `info`.

| What | Details |
| --- | --- |
| Cost | pixels drawn more than once |
| Found by | one look |
| Pattern | A page texture has mipmaps, anisotropic filtering, repeat, another pixel size than the atlas states, or a premultiplied image for a straight page. |

## MARROW024

| What | Details |
| --- | --- |
| Cost | memory, bytes sent to the GPU |
| Found by | one look |

| --- | --- |
| Cost | CPU time for the pose |

## MARROW026

**Uploads are larger on pixi.js before 8.23 with WebGL.** Its short name is `whole-buffer-upload-floor`, and its level is `info`.

| What | Details |
| --- | --- |
| Cost | bytes sent to the GPU |
| Found by | one look |
| Pattern | The game runs pixi.js 8.21 or 8.22 on WebGL2, and many skeletons change in a frame. |
| Runtime | Before pixi.js 8.23 a WebGL buffer keeps one stretch until Pixi binds it. So each buffer uploads one stretch, from the first change to the last. A data texture of `skinning: 'gpu'` uploads whole. From 8.23 the runtime uploads each stretch that changed. |
| Source | `src/render/batch-upload.ts` |
| Check | The tree dump states the pixi.js version and the renderer. |
| Fix | Use pixi.js 8.23 or later, or WebGPU. |
